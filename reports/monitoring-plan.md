# ESS 수명 예측 모델의 운영 모니터링 계획

작성일: 2026-10-01 · 계획 담당: 김영준

**운영 도입 시 적용을 검토할 잠정 제안이다.** 현재 수행 범위는 DAY1 EDA와 모델 설계이며, 학습된 최종 모델·운영 데이터·실제 BESS 연계가 없다. Live Test, drift 감시, 재학습, 배포는 모두 미실시다. 아래 주기와 판단 절차는 운영 자료의 양, 수명 라벨 지연, 운영자가 허용하는 오차를 확인한 뒤 확정한다. 실험실 셀의 결과를 실제 ESS 운영 성능으로 간주하지 않는다.

## 기준 자료와 책임

DAY2에서 최종 선택한 모델과 전처리, 피처 정의, 학습 데이터 해시, 학습 시점 및 검증 결과를 하나의 기준 버전으로 보존한다. 입력 비교 기준은 최종 모델을 학습한 자료의 분포·결측률·프로토콜 목록이다. 운영 데이터가 확보되면 별도 초기 운영 구간도 기록하고, 실험실 자료와 운영 자료의 차이를 먼저 평가한다. 비교 기준을 바꿀 때에는 변경 이유와 이전 기준을 남긴다.

김영준은 본 실습의 모니터링 계획·점검 기록 담당이다. 실제 운영 도입 시 경보 검토자와 배포 승인자는 운영 조직이 지정해야 하며, 이 문서가 실설비 접근이나 배포를 승인하는 것은 아니다. 셀/팩 식별자, 관측 기간, 적용 모델 버전, 입력, 예측값과 추후 확보한 수명 라벨을 연결해 기록한다.

## 잠정 점검 주기와 판단 방법

| 점검 | 잠정 주기 | 확인 항목과 경보 수립 방법 |
|---|---|---|
| 입력 품질 | 신규 수집일마다 일일 점검 | 필수 필드·단위·관측 범위·결측·비유한 값·중복 셀·신규 프로토콜 및 10/100사이클 대응을 확인한다. 스키마나 단위 불일치, 필요한 관측 미확보는 해당 예측을 보류하고 원인을 확인한다. 결측률과 수치 범위 경보는 학습 기준과 운영 허용 범위로 정한다. |
| Data Drift | 매월 점검 | 최근 한 달과 기준 자료의 ΔQ 로그 분산, 용량 변화, 온도·저항·충전 시간 및 충전 조건을 비교한다. 실제 채택 피처에 한정하며 분위수·분포·결측률·미등록 범주 비중을 함께 본다. 표본이 적으면 비교 기간을 늘리고 셀/프로토콜 구성 차이를 기록한다. |
| Model Drift | 라벨 확보 현황을 매월 확인하고, 충분한 라벨이 있으면 분기별 평가 | 예측 시점에 확정된 모델의 예측과 이후 확보한 총 수명을 연결해 MAPE(%)·RMSE(사이클)를 계산한다. 배치/프로토콜별 오차와 유효 표본 수, 라벨 확보까지의 지연을 함께 기록한다. |
| 기준·재학습 필요성 검토 | 분기별 정기 검토, 경보 발생 시 수시 검토 | 신규 자료의 양·대표성, 지속적인 분포 차이, 라벨 기반 성능 저하, 충전 정책/장비 변경을 검토해 재학습 여부를 결정한다. 정기 검토가 자동 재학습을 의미하지는 않는다. |

분포 차이는 성능 하락의 원인 후보를 알려주는 **Data Drift** 신호다. 수명 라벨로 확인한 예측 오차 악화는 **Model Drift** 점검 대상이다. 입력 변화만으로 성능이 나빠졌다고 확정하지 않는다. 수명 라벨은 오래 살아남은 셀에서 늦게 확보되므로, 먼저 관측된 단수명 셀만의 오차를 전체 운영 성능으로 일반화하지 않는다. 라벨 미확보·진행 중인 셀 수와 관측 기간을 별도로 보고한다.

분포 거리, 결측률, 성능 악화에 적용할 **절대 수치 임계값과 최소 표본 수는 아직 검증되지 않았다.** 학습·내부 검증에서의 변동, 초기 운영 기준 구간, 운영 허용 오차와 경보 빈도를 함께 검토해 도입 전에 정한다. 허용 범위 밖 변화가 반복되거나 필수 관측·단위 문제가 발생하면 경보를 검토하며, 작은 표본 한 번의 변동만으로 재학습을 결정하지 않는다.

## 경보 이후 재평가·재학습·승격·복구

경보가 발생하면 데이터 수집/센서/단위/프로토콜 파싱 문제를 먼저 조사한다. 품질 문제가 있으면 자료를 바로잡고 영향받은 예측 범위를 기록한다. 예측 입력이 실제 지원 범위를 벗어나면 운영자의 별도 판단이 필요함을 표시한다.

지속적인 성능 저하가 라벨로 확인되거나 충전 정책·대상 셀 특성이 바뀌고 충분한 신규 라벨이 확보되면 재학습 후보를 만든다. 기존 Batch 2 결과를 반복 튜닝 기준으로 사용하지 않으며, 새 자료에서도 셀·시간·프로토콜 경계를 지킨 학습/검증/독립 평가 구간을 마련한다. 대치·표준화·피처 선택은 학습 부분에서만 수행한다.

후보 모델은 사전에 정한 주 지표와 보조 지표, 주요 운영 그룹의 오차, 지원 범위·결측 처리·재현성을 기존 모델과 비교한다. 독립 평가에서 개선 또는 운영 허용 수준을 확인하고 특정 그룹의 허용할 수 없는 악화가 없을 때 운영 승인자가 승격 여부를 결정한다. 승격 전 기존 모델·전처리·설정으로 되돌릴 수 있도록 버전과 평가 결과를 보존한다.

배포 후 입력 처리 오류, 사전 합의한 허용 오차 초과, 특정 그룹의 지속적인 악화가 확인되면 원인을 조사하고 이전 검증 버전으로 복구하거나 예측 사용을 보류한다. 복구와 재배포의 이유·시점·영향 범위를 기록한다. 이 승격·복구 절차 역시 운영 자료로 검증되거나 실제 수행된 결과가 아니다.
